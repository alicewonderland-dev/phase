## HEADLINE CORRECTION TO THE ISSUE

The issue names the seam as `oracle_target.rs::parse_type_phrase` / `oracle_util.rs::merge_or_filters` /
`oracle_nom/filter.rs`. **That is measurably wrong.** `parse_type_phrase` handles Oxford-comma type lists
of any arity correctly today, for subtypes and core types alike.

The real seam for consumer 1 is the **trigger condition/effect boundary** in
`crates/engine/src/parser/oracle_trigger.rs`. The boundary scanner walks *past* the commas of the effect
clause's own type list and lands on the LAST one, so the effect text handed to the effect parser is only
the final list item. `parse_type_phrase` then parses that one item perfectly — which is why the AST looks
like a clean, warning-free `Typed{Subtype("Rat")}`.

Consumers 2 (protection lists) and 4 (quantity counts) are **already correct at the arity the issue
complains about** — measured, not assumed. Consumer 3 (`except for` exclusions) is broken by a
**different, independent** root cause.

Claims are labelled `[PROBED]` (round 1: measured by a compiled scratch driver against the real
`parse_oracle_text`), `[DATA]` (measured with `jq` against the engine-generated `client/public/card-data.json`,
98 MB, present on disk at BASE_SHA; round-3 additions re-measured by me), `[SCRYFALL]` (measured by me
against the live Scryfall API this round), or `[TRACED]` (read from source, not executed).
**No claim in this plan is `[PROBED]` for the post-fix tree** — the planner may not edit production code,
so every post-fix verdict below is `[TRACED]` from the combinator sources I read, and the implementer
owes the post-fix probe and the corpus diff named in Verification Steps §5 and §6.

## Root-cause analysis

### Cause A — consumer 1

`crates/engine/src/parser/oracle_trigger.rs`

1. `split_trigger` (`:9723`) splits the trigger line at `find_effect_boundary(tp.lower)` — note the input
   is **already lowercased**, an invariant U1's new code relies on and documents.
2. `find_effect_boundary` (`:9788`) walks every `", "` left-to-right with
   `nom_primitives::split_once_on` and returns the first comma that **none** of its five continuation
   guards claims. `continues_player_action_list` is one of them (called `:9792`).
3. `continues_player_action_list` (`:9854`) ends at:
   ```rust
   if !starts_with_type_word(after_conjunction) { return false; }
   !is_new_sentence_not_type_continuation(after_conjunction)
   ```
4. **`is_new_sentence_not_type_continuation` (`:9945`) is the defect.** Its window is ONE list item:
   ```rust
   let clause = text.split(", ").next().unwrap_or(text);   // one item
   let lower = clause.to_lowercase();
   lower.split_whitespace().skip(1).any(|w| { … PREDICATE_VERBS … is_negated_auxiliary_predicate_token … })
   ```
   It has **exactly one** call site — `grep -rn is_new_sentence_not_type_continuation crates/engine/src/`
   returns only the definition and that one call.

Trace for `whenever this creature attacks, birds, frogs, otters, and rats you control get +1/+1 until end of turn.`:

| comma | `after` | narrow window | words after head | verdict |
|---|---|---|---|---|
| 1 | `birds, frogs, otters, and rats you control get …` | `"birds"` | *(none)* | continuation -> skip |
| 2 | `frogs, otters, and rats you control get …` | `"frogs"` | *(none)* | continuation -> skip |
| 3 | `otters, and rats you control get …` | `"otters"` | *(none)* | continuation -> skip |
| 4 | strip `and ` -> `rats you control get …` | whole (no more `", "`) | `you control get …` -> **`get`** in `PREDICATE_VERBS` | **new sentence -> BOUNDARY** |

`condition = "Whenever ~ attacks, Birds, Frogs, Otters"`, `effect = "and Rats you control get +1/+1 …"`.
`parse_type_phrase` then does its job perfectly on `Rats you control`. The polluted `valid_card` is a
*downstream* consequence: `parse_trigger_condition` receives the already-split condition text and the
SpellCast arm inside `try_parse_player_trigger` parses the swallowed list into `valid_card`.

Why the leading-`each` form escapes: `starts_with_type_word("each advisor, …")` is false, so the guard
short-circuits and the very first comma is the boundary — which is why The Archimandrite is correct
today. Why the 2-item non-Oxford form escapes: `Birds and Rats you control get …` contains no `", "` at
all, so the narrow window is already the whole clause. The 2-item **Oxford** form (`Birds, and Rats`)
does NOT escape and is broken today `[PROBED]`.

- No new types, no new enum variants, no `bool` parameters, no wildcard-swallowing `match`.
- `type_list_clause_window` returns `&str` — a true subslice of its input, slice arithmetic only, no

- The postmodifier bound is a **combinator** (`parse_type_list_postmodifier_start`), matching this
  file's `parse_non_event_complement` idiom (`value((), tag(..)).parse(input)` with the error type
  inferred from the `OracleResult` return), never a `contains("that ")`.
- The widened-pass classifier is a *derived* predicate over two existing authorities

#### U1.0 — The two halves of the safety argument

`find_effect_boundary` returns the **first** comma that no continuation guard claims.
`continues_player_action_list` returns `!is_new_sentence_not_type_continuation(after)`. Therefore:

> Making `is_new_sentence_not_type_continuation` return `true` more often moves the boundary **earlier
> or leaves it**. Making it return `false` more often moves the boundary **later, or removes it
> entirely** (`find_effect_boundary -> None`, which makes `split_trigger` return an empty effect).

There are consequently **two** things to prove, and round 2 proved only the first:

- **(H1) "Later is unsafe" — discharged by monotonicity.** No verdict that is `true` today may become
  `false`, or a trigger loses its effect clause. Theorem 1.
- **(H2) "Earlier is also unsafe" — NOT discharged by monotonicity, and this is where round 2 failed.**
  A boundary that moves *earlier* truncates the **condition**. Round 2's §Pattern Coverage asserted the
  condition side was empty ("census returns 0 genuine cards"); it is not (census C3: **33 printed
  cards**), and one of them — **Immolation Shaman** — is measurably regressed by round 2's rule.
  Theorems 3a/3b and the corpus argument below discharge H2 with evidence.

Round 1's design — `PREDICATE_VERBS AND NOT parse_event_head_start` applied to the whole widened window
— violated H1, and two printed cards prove it `[DATA]`:

#### U1.1 — The design, stated as theorems

Let, for a post-comma text `x` (always lowercase — `find_effect_boundary(tp.lower)`):

- `W_narrow(x)` = today's window, `x` up to the first `", "` (or all of `x`).
- `B(x)` = **the scan-stop offset**, `type_list_clause_window(x).len()`: the Oxford-type-list span,
  bounded **first** at the sentence (`". "`), **then** at the first restrictive postmodifier
  (`that ` / `which ` / `with ` at a word boundary), **then** extended across every following `", "`
  whose remainder `starts_with_type_list_continuation` accepts. `type_list_clause_window` returns a
  **prefix slice of `x`**, so its length is a byte offset into `x`.
- `P(w)` = `w` is an effect predicate: `PREDICATE_VERBS.contains(normalize_verb_token(w))` or
  `is_negated_auxiliary_predicate_token(w)`. (Unchanged from today; both passes use it via
  `clause_has_effect_predicate`.)
- `E(t) = parse_event_head_start(t).is_ok()` at the **UNBOUNDED** tail `t` — `t` is the suffix of `x`
  beginning at that word and running to the end of the line, **never** a slice of the window.
  **[REVISED r4 — G1, the structural repair.]**

Today: `old(x) = exists w in words(W_narrow(x)).skip(1) : P(w)`.

**New:**
```
new(x) = old(x)                                  // pass 1 - legacy verdict, unchanged
       or first_classifier(x, B(x)) == Predicate  // pass 2 - offset-stopped, event-head-priority
```
where `first_classifier` walks the word boundaries of `x` after its head word, left to right, and at
each tail `t` (a suffix of `x`) with head word `w`, at byte offset `o = x.len() - t.len()`, returns:

1. **stop** (verdict `false`) if `o >= B(x)` — past the type list;
2. else **`Event`** if `E(t)`;
3. else **`Predicate`** if `P(w)`;
4. else advance.

`None` (verdict `false`) if it runs off the end. Event is tested **before** predicate at the same word,
so a word that is both — `attacks`, `becomes`, `casts` — is read as the trigger event.

**Theorem 1 (monotonicity — discharges H1).** `old(x) => new(x)`, by the disjunction. Hence no verdict
that is `true` today can become `false`; `continues_player_action_list` can only lose `true` verdicts,
and `find_effect_boundary`'s returned index is **monotonically non-increasing** — a boundary may move
earlier or stay, never later, and `Some(_)` can never become `None`.
*Corollary:* **no trigger line can lose its effect clause.** The Thanos-Copter and Spellbinding Soprano

**Theorem 2 (the event-head exclusion is confined).** Pass 2 is reached only when `old(x)` is `false`,

pass 2 lies **strictly beyond `W_narrow(x)`**, and `E` can only ever suppress a verdict that today's
code does not reach. A **false positive** of `parse_event_head_start` is consequently *benign by
construction*: it can only decline the new verdict, never the old one.

The scan-stop is CR 608.2c grammar, not a card patch: a relative clause (`that`/`which`) or a

  **is** in `PREDICATE_VERBS` and is **not** an event head. Zero printed cards today, but the

/// CR 608.2c ("read the whole text and apply the rules of English"): the lead of
/// a RESTRICTIVE POSTMODIFIER — a relative clause ("that isn't a mana ability",
/// "which has flying") or a "with ..." phrase. A postmodifier attaches to the
/// noun phrase it follows, so every verb inside it belongs to THAT noun phrase
/// and can never be the main verb of a following clause. Bounds
/// [`type_list_clause_window`].
///
/// Measured (issue #7451): without this bound, Immolation Shaman's "an ability
/// of an artifact, creature, or land THAT ISN'T a mana ability" lets the widened
/// window reach "isn't", which `is_negated_auxiliary_predicate_token` classifies
/// as an effect predicate and `parse_event_head_start` cannot suppress (its
/// passive arm requires "is "/"are "). The boundary would move from the card's
/// second comma to its first and narrow `valid_card` from
/// AnyOf[Artifact, Creature] to Artifact.
///
/// This bounds WHERE THE SCAN STOPS, never what a parser is handed: pass 2 always
/// evaluates `parse_event_head_start` on the full, unbounded tail. Handing the
/// event parser a truncated slice would be unsound — `parse_event_phrase` is a
/// bare `tag(phrase)` with no boundary peek (:9271-:9274), so a slice ending
/// right after "deals"/"cast"/"draw"/... loses the Event match and the same word
/// is re-read as a `PREDICATE_VERBS` hit, i.e. a SHRINKING window could flip a
/// verdict toward `true`. See the monotonicity paragraph on
/// [`is_new_sentence_not_type_continuation`].
fn parse_type_list_postmodifier_start(input: &str) -> OracleResult<'_, ()> {
    value((), alt((tag("that "), tag("which "), tag("with ")))).parse(input)
}

/// The span of ONE Oxford-comma type list, starting at `text`'s head type word.
///
/// Returns a PREFIX SLICE of `text`, so `.len()` is a byte offset into `text` —
/// that offset is the ONLY thing the caller uses (see
/// [`is_new_sentence_not_type_continuation`]'s pass 2, which stops its word scan
/// there while still handing every parser the unbounded tail).
///
/// `text` is always lowercase: the sole consumer chain is
/// `split_trigger` -> `find_effect_boundary(tp.lower)` ->
/// `continues_player_action_list` -> `is_new_sentence_not_type_continuation`.
///
/// THREE BOUNDS, IN THIS ORDER.
///
/// 1. CR 603.1 — a triggered ability is ONE sentence ("[When/Whenever/At]
///    [trigger condition or event], [effect]. [Instructions (if any).]"), so the
///    span is bounded at the sentence FIRST. Without it, a trailing instruction
///    sentence's verbs could decide this sentence's boundary (Valley
///    Floodcaller's "... until end of turn. Untap them.").
/// 2. CR 608.2c — then at the first restrictive postmodifier
///    ([`parse_type_list_postmodifier_start`]). See that fn's doc for the
///    measured card.
/// 3. CR 205.2a + CR 205.3a — then extended across every `", "` whose remainder
///    `starts_with_type_list_continuation` accepts, i.e. the same authority the
///    SpellCast payload truncation already uses (issue #5324, Sram), stopping at
///    the first comma that is not a list continuation. Reading a comma inside a
///    type list as a set-union separator rather than a clause boundary is the
///    "rules of English" reading CR 608.2c mandates; CR 205.2a/205.3a supply
///    only the vocabularies ("these words are card types / subtypes").
fn type_list_clause_window(text: &str) -> &str {
    let sentence = match nom_primitives::split_once_on(text, ". ") {
        Ok((_, (before, _))) => before,
        Err(_) => text,
    };
    let bounded = match nom_primitives::scan_split_at_phrase(
        sentence,
        parse_type_list_postmodifier_start,
    ) {
        Some((before, _)) => before.trim_end(),
        None => sentence,
    };
    let mut consumed = 0usize;
    let mut tail = bounded;
    loop {
        let Ok((_, (before, rest))) = nom_primitives::split_once_on(tail, ", ") else {
            return bounded;
        };
        if !starts_with_type_list_continuation(rest) {
            return &bounded[..consumed + before.len()];
        }
        consumed += before.len() + ", ".len();
        tail = rest;
    }
}

/// The LEGACY effect-predicate test, lifted out of
/// [`is_new_sentence_not_type_continuation`] so the monotonicity argument in
/// that function's doc-comment is mechanically checkable: BOTH passes call this
/// one function, and its behavior must stay identical to the pre-#7451 test.
///
/// CR 608.2c: negated modal verbs ("can't", "doesn't", "isn't") head a
/// restriction predicate and count as a predicate, via
/// [`is_negated_auxiliary_predicate_token`]. They are only trustworthy as an
/// EFFECT signal inside a main clause, which is why the pass-2 window is bounded
/// at a restrictive postmodifier before this is applied there.
fn clause_has_effect_predicate(clause: &str) -> bool {
    use crate::parser::oracle_effect::normalize_verb_token;
    use crate::parser::oracle_effect::subject::PREDICATE_VERBS;

    let lower = clause.to_lowercase();
    // Skip the head type word itself and check the remaining words.
    lower.split_whitespace().skip(1).any(|w| {
        PREDICATE_VERBS.contains(&normalize_verb_token(w).as_str())
            || is_negated_auxiliary_predicate_token(w)
    })
}

/// Check whether the text starting at a type word is a new subject-predicate
/// sentence (the trigger's EFFECT) rather than a continuation of the trigger
/// CONDITION's own type list.
///
/// TWO PASSES, AND THE ORDER IS THE CONTRACT.
///
/// Pass 1 is [`clause_has_effect_predicate`] over TODAY'S one-item window and is
/// behaviorally identical to the pre-#7451 test. Pass 2 only runs when pass 1
/// says "continuation".
///
/// MONOTONICITY (load-bearing, do not restructure into a single pass). This
/// predicate feeds `continues_player_action_list`, hence `find_effect_boundary`,
/// hence the condition/effect split of EVERY trigger line containing ", "
/// (measured: 15307 corpus cards have at least one such trigger line).
/// Returning `true` more often moves the boundary EARLIER; returning `false`
/// more often moves it LATER or removes it, swallowing effect text into the
/// condition. Because pass 2 is a DISJUNCT, no verdict that is `true` today can
/// become `false`: The Thanos-Copter's "Vehicles you control become artifact
/// creatures" and Spellbinding Soprano's "instant and sorcery spells you cast

/// trigger events and DELETE their effect clauses outright. A single-pass
/// "widened window AND not an event head" form does exactly that; it was
/// measured and rejected (#7451 round 1).
///
/// MOVING A BOUNDARY EARLIER IS ALSO UNSAFE, and monotonicity does NOT cover it:
/// it truncates the CONDITION. That is what [`type_list_clause_window`]'s two
/// bounds exist for. Measured (#7451 round 2): with only the sentence bound,
/// Immolation Shaman's "an ability of an artifact, creature, or land that isn't
/// a mana ability" moved from its second comma to its first and narrowed
/// `valid_card` from AnyOf[Artifact, Creature] to Artifact. 33 printed cards

/// ([`type_list_clause_window`]), not its first item. The one-item window saw
/// only "birds" in "Birds, Frogs, Otters, and Rats you control get +1/+1", so
/// `find_effect_boundary` walked to the LAST list comma and the effect kept only
/// the final item (issue #7451, Valley Floodcaller). Core-type lists collapsed
/// identically ("artifacts, creatures, and lands" -> Land), which is why the
/// WINDOW — not the subtype vocabulary — is the fix.
///
/// EVENT HEADS WIN TIES — CR 603.1 + CR 603.2e. `PREDICATE_VERBS` and the
/// trigger-event lexicon overlap on TWELVE roots that are the SAME WORD in both:
/// attack(s), block(s), become(s), deal(s), sacrifice(s), discard(s), cast(s),
/// create(s), draw(s), transform(s), explore(s), phase(s in/out). (Enumerated by
/// intersecting the 47-entry `PREDICATE_VERBS` with `parse_event_verb_start` +
/// `parse_state_change_event_start` at BASE_SHA. "mill" is in `PREDICATE_VERBS`
/// only; "play", "enters", "dies", "leaves" and "cycle" are in the event lexicon
/// only.) Pass 2 therefore scans left to right and asks `parse_event_head_start`
/// BEFORE the predicate test at each word: in a CR 603.1 sentence the first
/// classifying token after a type list belongs to the trigger event if the event
/// lexicon claims it.
///
/// A THIRTEENTH overlap is NOT same-word and is why the scan must be ORDERED
/// rather than a whole-window veto: "put" is a predicate verb, but the event
/// lexicon's entry is the phrase "is put into" (`parse_event_verb_start`,
/// oracle_trigger.rs:9290), whose head "is" is reached one word EARLIER. The
/// ordered scan classifies "is put into" as an Event before "put" can be read as
/// a predicate.
///
/// Both authorities are consulted as PARSERS, never restated as a local verb
/// list, so this stays in lockstep as either table grows.
fn is_new_sentence_not_type_continuation(text: &str) -> bool {
    // Pass 1 — legacy verdict over the one-item window. PATTERNS.md section 6:
    // `split_once_on` is the combinator form of the former `text.split(", ")`.
    let narrow = match nom_primitives::split_once_on(text, ", ") {
        Ok((_, (before, _))) => before,
        Err(_) => text,
    };
    if clause_has_effect_predicate(narrow) {
        return true;
    }

    // Pass 2 — widened, bounded window; event-head-priority word scan
    // (PATTERNS.md section 5). Reached only when pass 1 found no predicate at
    // all, so every classification below lies strictly beyond the one-item
    // window.
    use crate::parser::oracle_effect::normalize_verb_token;
    use crate::parser::oracle_effect::subject::PREDICATE_VERBS;

    let window = type_list_clause_window(text).to_lowercase();
    let after_head = match nom_primitives::split_once_on(&window, " ") {
        Ok((_, (_, rest))) => rest,
        Err(_) => return false,
    };
    nom_primitives::scan_at_word_boundaries(after_head, |tail: &str| {
        // CR 603.1 + CR 603.2e: an event head belongs to the trigger CONDITION.
        if parse_event_head_start(tail).is_ok() {
            return Ok((tail, false));
        }
        let word = tail.split_whitespace().next().unwrap_or(tail);
        if PREDICATE_VERBS.contains(&normalize_verb_token(word).as_str())
            || is_negated_auxiliary_predicate_token(word)
        {
            return Ok((tail, true));
        }
        Err(oracle_err(tail))
    })
    .unwrap_or(false)
}

touching precedence.

### The #6857 fixture edit, corrected **[REVISED r3 — F4]**

`tests/integration/jeskai_ascendancy_pump_untap_anaphora_6857.rs::valley_floodcaller_untaps_exactly_the_creatures_it_pumped`

today and would still pass unchanged after the fix** — but round 2 mandated strengthening it to assert
the population is exactly `{bird, frog, otter, rat, valley floodcaller}`, and **that assertion cannot
pass as specified**, for two independent reasons measured this round:

1. The fixture builds the Floodcaller with `scenario.add_creature_from_oracle(P0, "Valley Floodcaller", 2, 2, …)`

   `assert_eq!(published_set(runner.state()), pumped)` (`:984`) — an assertion that belongs to #6857.
