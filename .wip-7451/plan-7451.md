## HEADLINE CORRECTION TO THE ISSUE

The issue names the seam as `oracle_target.rs::parse_type_phrase` / `oracle_util.rs::merge_or_filters` /
`oracle_nom/filter.rs`. **That is measurably wrong.** `parse_type_phrase` handles Oxford-comma type lists
of any arity correctly today, for subtypes and core types alike.

The real seam for consumer 1 is the **trigger condition/effect boundary** in
`crates/engine/src/parser/oracle_trigger.rs`. The boundary scanner walks *past* the commas of the effect
clause's own type list and lands on the LAST one, so the effect text handed to the effect parser is only
the final list item. `parse_type_phrase` then parses that one item perfectly — which is why the AST looks
like a clean, warning-free `Typed{Subtype("Rat")}`.

Consumers 2 (protection lists) and 4 (quantity counts) are **already correct at the arity the issue
complains about** — measured, not assumed. Consumer 3 (`except for` exclusions) is broken by a
**different, independent** root cause.

Claims are labelled `[PROBED]` (round 1: measured by a compiled scratch driver against the real
`parse_oracle_text`), `[DATA]` (measured with `jq` against the engine-generated `client/public/card-data.json`,
98 MB, present on disk at BASE_SHA; round-3 additions re-measured by me), `[SCRYFALL]` (measured by me
against the live Scryfall API this round), or `[TRACED]` (read from source, not executed).
**No claim in this plan is `[PROBED]` for the post-fix tree** — the planner may not edit production code,
so every post-fix verdict below is `[TRACED]` from the combinator sources I read, and the implementer
owes the post-fix probe and the corpus diff named in Verification Steps §5 and §6.

### Consumer 2 — protection lists — **ALREADY CORRECT AT ARITY** `[DATA]`

is a real (separate, pre-existing) gap. It is **out of scope for #7451**, is not made worse here, and V2
is labelled and worded accordingly.

private `source_subtype_matches_protection_quality` (`keywords.rs:688`), which is `parse_subtype(quality)`
with a full-consume check — so the printed plural (`"krakens"`) is normalised to `"Kraken"` at match
time `[TRACED]`. Consumer 2 needs a **regression pin**, not a fix.

does NOT escape and is broken today `[PROBED]`.

### Design decision: `TargetFilter::Or` legs, NOT a `TypeFilter::AnyOf` union — and why

This is the representation question the issue asks for, and the answer is *neither leg of the fix
chooses it* — the representation is not the defect. Stated explicitly anyway, because it constrains the
implementer:

**Use `TargetFilter::Or` of per-item `Typed` legs. Do not introduce `TypeFilter::AnyOf` here.**

1. **Both existing authorities already emit `Or`.** `parse_subtype_list_filter` (static seam) and
   `parse_type_phrase_with_ctx`'s separator recursion (target seam) both produce `Or`, and both are
   `[PROBED]` correct. Emitting `AnyOf` from a third site would make three representations of one concept.
2. **`Or` is the shape the distribution machinery is built around.** `finalize_or_disjunction` (`:4341`)
   runs `distribute_controller_to_or` -> `distribute_core_type_to_or` -> `distribute_neg_type_filters_to_or`
   -> `distribute_shared_properties` -> `distribute_properties_to_or`. `distribute_controller_to_or`
   (`:5191`) back-fills the controller harvested from the *last* leg onto every earlier leg — exactly how
   `Birds, Frogs, Otters, and Rats you control` gets `controller: You` on all four legs though
   `you control` is printed once, at the end. An `AnyOf` union inside a single `Typed` would bypass all
   five distributors.

#### U1.0 — The two halves of the safety argument

`find_effect_boundary` returns the **first** comma that no continuation guard claims.
`continues_player_action_list` returns `!is_new_sentence_not_type_continuation(after)`. Therefore:

> Making `is_new_sentence_not_type_continuation` return `true` more often moves the boundary **earlier
> or leaves it**. Making it return `false` more often moves the boundary **later, or removes it
> entirely** (`find_effect_boundary -> None`, which makes `split_trigger` return an empty effect).

There are consequently **two** things to prove, and round 2 proved only the first:

- **(H1) "Later is unsafe" — discharged by monotonicity.** No verdict that is `true` today may become
  `false`, or a trigger loses its effect clause. Theorem 1.
- **(H2) "Earlier is also unsafe" — NOT discharged by monotonicity, and this is where round 2 failed.**
  A boundary that moves *earlier* truncates the **condition**. Round 2's §Pattern Coverage asserted the
  condition side was empty ("census returns 0 genuine cards"); it is not (census C3: **33 printed
  cards**), and one of them — **Immolation Shaman** — is measurably regressed by round 2's rule.
  Theorems 3a/3b and the corpus argument below discharge H2 with evidence.

Round 1's design — `PREDICATE_VERBS AND NOT parse_event_head_start` applied to the whole widened window
— violated H1, and two printed cards prove it `[DATA]`:

| Card | Today | Under round 1's rule |
|---|---|---|

#### U1.1 — The design, stated as theorems

Let, for a post-comma text `x` (always lowercase — `find_effect_boundary(tp.lower)`):

- `W_narrow(x)` = today's window, `x` up to the first `", "` (or all of `x`).
- `B(x)` = **the scan-stop offset**, `type_list_clause_window(x).len()`: the Oxford-type-list span,
  bounded **first** at the sentence (`". "`), **then** at the first restrictive postmodifier
  (`that ` / `which ` / `with ` at a word boundary), **then** extended across every following `", "`
  whose remainder `starts_with_type_list_continuation` accepts. `type_list_clause_window` returns a
  **prefix slice of `x`**, so its length is a byte offset into `x`.
- `P(w)` = `w` is an effect predicate: `PREDICATE_VERBS.contains(normalize_verb_token(w))` or
  `is_negated_auxiliary_predicate_token(w)`. (Unchanged from today; it is named once as
  `token_is_effect_predicate`, and both passes consult THAT — pass 1 through
  `clause_has_effect_predicate`, pass 2 directly. **[REVISED r6 — MATERIAL 2.]**)
- `E(t) = parse_event_head_start(t).is_ok()` at the **UNBOUNDED** tail `t` — `t` is the suffix of `x`
  beginning at that word and running to the end of the line, **never** a slice of the window.
  **[REVISED r4 — G1, the structural repair.]**

Today: `old(x) = exists w in words(W_narrow(x)).skip(1) : P(w)`.

**New:**
```
new(x) = old(x)                                  // pass 1 - legacy verdict, unchanged
       or first_classifier(x, B(x)) == Predicate  // pass 2 - offset-stopped, event-head-priority
```
where `first_classifier` walks the word boundaries of `x` after its head word, left to right, and at
each tail `t` (a suffix of `x`) with head word `w`, at byte offset `o = x.len() - t.len()`, returns:

1. **stop** (verdict `false`) if `o >= B(x)` — past the type list;
2. else **`Event`** if `E(t)`;
3. else **`Predicate`** if `P(w)`;
4. else advance.

`None` (verdict `false`) if it runs off the end. Event is tested **before** predicate at the same word,
so a word that is both — `attacks`, `becomes`, `casts` — is read as the trigger event.

**Theorem 1 (monotonicity — discharges H1).** `old(x) => new(x)`, by the disjunction. Hence no verdict
that is `true` today can become `false`; `continues_player_action_list` can only lose `true` verdicts,
and `find_effect_boundary`'s returned index is **monotonically non-increasing** — a boundary may move
earlier or stay, never later, and `Some(_)` can never become `None`.
*Corollary:* **no trigger line can lose its effect clause.** The Thanos-Copter and Spellbinding Soprano
are both decided `true` inside `W_narrow`, so pass 1 short-circuits and their verdicts are unchanged
without the exclusion or the widened window ever being consulted.

**Theorem 2 (the event-head exclusion is confined).** Pass 2 is reached only when `old(x)` is `false`,
i.e. every word in `W_narrow(x)` after the head fails `P`. Therefore any `Predicate` classification in
pass 2 lies **strictly beyond `W_narrow(x)`**, and `E` can only ever suppress a verdict that today's
code does not reach. A **false positive** of `parse_event_head_start` is consequently *benign by
construction*: it can only decline the new verdict, never the old one.
**[REVISED r3 — the residual-risk bound is restated correctly.]** Round 2 wrote that the only residual
risk is "a false negative — an unrecognised event verb that is also in `PREDICATE_VERBS`". That bound is
**wrong**, because it silently assumes every pass-2 `Predicate` verdict comes from the
`PREDICATE_VERBS` table. It does not: `P` has a **second** disjunct,
`is_negated_auxiliary_predicate_token`, which `parse_event_head_start` cannot suppress at all
(`parse_state_change_event_start`'s passive arm requires `tag("is ")`/`tag("are ")`; `"isn't"` matches
neither). Immolation Shaman fires on exactly that branch. The correct residual-risk statement is:
> pass 2 can produce a spurious `Predicate` from **any** `P`-word that lies beyond the narrow window and
> is not itself an event head — whether it comes from `PREDICATE_VERBS` (`have`, `get`, `deal`, …) or
> from the negated-auxiliary branch (`isn't`, `can't`, `doesn't`, …). Both cases are the SAME
> structural error: the word is not a main-clause verb at all, it sits inside a **restrictive
> postmodifier** attached to the last list item. That is what Theorem 3b's scan-stop bound removes, and
> it removes both cases at once.

**Theorem 3a (the event-head exclusion is load-bearing).** Without `E`, pass 2 fires on condition-side
type lists whose event verb sits beyond the narrow window. For

`PREDICATE_VERBS`, so the boundary
would move from comma 2 (today) to comma 1, yielding condition `"Whenever a bird"` and effect
`"frog, or otter you control attacks, draw a card"` — **strictly worse than today**. With `E`, the scan
classifies `attacks` as `Event` and returns `false`, leaving today's comma-2 boundary intact. The same

The scan-stop is a **general grammar rule, not a card patch** — but it is a rule of ENGLISH applied at
parse time, **derived BY ANALOGY from CR 608.2c's "read the whole text and apply the rules of English to
the text" instruction; the CR states no rule about noun-phrase attachment. [REVISED r5 — M7.]** 608.2c's
verbatim subject (`docs/MagicCompRules.txt:2797`, re-grepped this round) is resolution-time instruction
ordering — "The controller … follows its instructions in the order written… later text on the card may
modify the meaning of earlier text… read the whole text and apply the rules of English to the text." It
genuinely licenses U3 (later text modifying an earlier population phrase). It does **not** state anything
about relative-clause attachment, and nothing about reading a comma as set union. What the analogy
licenses is that we are entitled to read English at all; the attachment rule itself is ours. The reading:
a relative clause (`that`/`which`) or a `with`-postmodifier attaches to the noun phrase it follows, so
any verb inside it belongs to **that noun phrase** — here, the trigger condition's object — and can never
be the main verb of the effect clause. This is the same demotion r4 applied to the event-head tie-break
("an engineering heuristic derived from CR 603.1, not a rule the CR states"); r4 moved the *window*
heading onto 608.2c without applying it there, which is what r5 finishes.
Two independent consequences, both class-level:
- it removes the `is_negated_auxiliary_predicate_token` exposure (Immolation Shaman), **and**
- it removes the `PREDICATE_VERBS` exposure of the same shape — e.g. a hypothetical
  `"…of an artifact, creature, or land that has flying, …"`, where `has` normalises to `have`, which
  **is** in `PREDICATE_VERBS` and is **not** an event head. Zero printed cards today, but the
  protection is structural rather than accidental.

**(i) The Containment lemma — now a theorem, and it says only what it says.**

> **Containment lemma.** Let `pass2_r2` be the round-2 predicate (sentence bound + comma walk, no

> `{x : pass2_r4(x)} ⊆ {x : pass2_r2(x)}`.

> 1. **A word's verdict no longer depends on the bound.** `E(t)` is evaluated on the unbounded tail

>    is a `tag`/`terminated(tag, parse_event_boundary)`, so a match on the prefix implies a match on
>    the longer string (the r2 window ends at `.` or `,`, both of which `parse_event_boundary`
>    accepts). Hence `E_r2(o) => E_r4(o)`: r4 classifies `Event` at least as often, i.e. suppresses
>    `Predicate` at least as often.
>    Sub-case: the r4 scan walks the word boundaries of the FULL `x` and stops at offset `B(x)`,

>    sequence at every position `< B(x)`. **[REVISED r5 — B3.]** The property this needs is **not**

///    here rather than an authority.
/// 3. CR 205.2a + CR 205.3a — then extended across every `", "` whose remainder
///    `starts_with_type_list_continuation` accepts, i.e. the same authority the
///    SpellCast payload truncation already uses (issue #5324, Sram), stopping at

fn type_list_clause_window(text: &str) -> &str {

        Ok((_, (before, _))) => before,
        Err(_) => text,
    };
    let bounded = match nom_primitives::scan_split_at_phrase(
        sentence,
        parse_type_list_postmodifier_start,
    ) {
        Some((before, _)) => before.trim_end(),
        None => sentence,

            return bounded;
        };

            return &bounded[..consumed + before.len()];
        }
        consumed += before.len() + ", ".len();
        tail = rest;
    }
}

/// CR 608.2c: negated modal verbs ("can't", "doesn't", "isn't") head a
/// restriction predicate and count as a predicate, via

fn token_is_effect_predicate(word: &str) -> bool {

    use crate::parser::oracle_effect::subject::PREDICATE_VERBS;
    PREDICATE_VERBS.contains(&normalize_verb_token(word).as_str())

/// The LEGACY clause-level verdict, lifted out of

fn clause_has_effect_predicate(clause: &str) -> bool {
    let lower = clause.to_lowercase();

}

        Ok((_, (before, _))) => before,
        Err(_) => text,

        return true;

    // (PATTERNS.md section 5), stopped at the end of the type list. Reached

    // tail the scan yields below is a suffix of the FULL line.

        Err(_) => return false,

        if token_is_effect_predicate(word) {
            return Ok((tail, true));
        }
        Err(oracle_err(tail))
    })
    .unwrap_or(false)
}
